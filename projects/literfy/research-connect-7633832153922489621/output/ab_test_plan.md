- Product: Literfy
- Reference pattern: research.connect Google Scholar hook + command-style captions
- Footage: V2 approved visual sequence
- Duration: ~35s
- Changed variable: caption copy only

## Variant B - Pain Question

File: `/Users/kk/Desktop/auto video/projects/literfy/research-connect-7633832153922489621/output/final_video_captioned_ab_b.mp4`

Hypothesis: A direct pain question may improve first-3-second retention because it names the user's current bad workflow.

Opening:

```text
Still starting your literature review with random Google Scholar tabs?
```

Best use:

- Test if the audience responds better to pain recognition than status-upgrade framing.
- Good for students who already feel overwhelmed by search tabs.

## Variant C - Workflow Direct

File: `/Users/kk/Desktop/auto video/projects/literfy/research-connect-7633832153922489621/output/final_video_captioned_ab_c.mp4`

Hypothesis: A clearer utility promise may improve saves, but it is slightly less native than Variant A.

Opening:

```text
How to start a literature review without opening 50 tabs
```

Best use:

- Test if a more concrete workflow promise beats the PhD/Master status hook.

## Suggested Upload Order

1. Variant A as the baseline.
2. Variant B if A's hook retention is weak.
3. Variant C if comments/saves suggest users care more about workflow clarity than reference-style imitation.

## Metrics To Compare

- 2s hold rate / hook retention
- average watch time
- completion rate
- saves
- profile clicks / website clicks
- comments asking what tool/site it is

## Learning Rule

Only change one major variable at a time. These three versions keep the footage fixed and only test caption angle, so any performance difference is more likely caused by copy positioning.
